These operational names map to the implemented steps, not additional unimplemented routines. After every event, each state describes a realizable paid-action prefix, exact live occupancy and selected witness boundary/connectivity. Every feasible continuation's minimum label has an at-least-as-good retained representative. Future IDs are disjoint from processed prefix actions, so adding a common future set preserves cost, count and equal-cardinality sorted-ID order. Stored tuples and accumulated exact cost have polynomial bit length in $B$, where numeric costs mean the represented decoded values, not arbitrary-precision original JSON lexemes.

All parameters are computed: $p$ counts supplied profiles; $r$ is obtained by per-profile baseline contraction (all or safely marked); $z$ is constructed from rectangular cells; $L$ measures complete units/baseline spans; $h$ counts within-unit owners per cell; $g$ counts owners per unit. Recognition constructs the decomposition and is charged in $T_{\rm rec}$. The $prL$ term controls optional boundary sets/partitions and $zL\log(h+2)$ controls live owner maps; $g$ is descriptive, while $B$ controls polynomial arithmetic/identifier work.

An empty state set after exhaustive transitions means infeasible; a cap does not. The recognized implementation requires one supplied obligation source per profile. Empty obligation lists and profiles without an obligation are unsupported. A trivial source-equals-target obligation supplies a root and needs no purchase. These boundaries are part of the stated input class.
