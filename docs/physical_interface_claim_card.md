# Active claim card: ownership-aware physical interface repair

14 October 2026. Status: **developed candidate, not established originality**. The user's direction is to build a positive contribution in this family, using prior work as a baseline and addressing limitations rather than repeatedly abandoning the family.

## Exact research claim

For rooted multi-profile strict portal repair with an exact owned collision-cell model, bounded local interface size and bounded asset-coupling-unit support, there is a deterministic original-action algorithm with proposed bound

`recognition_time + 2^O(prL + zL log(g+2)) * polynomial(input_bit_size)`.

It supports many original actions sharing one consistent asset and indivisible shared-cost actions involving several assets. It preserves original cost/count/lexical ties and complete physical occupancy. See the [constructive proof](asset_unit_interface_theorem.md) for p,r,z,L,g and all assumptions.

## Why the class can have useful repair scenarios

- Local ramps, stairs and short-span lift alternatives within supplied vertical reservations can have small support windows.
- Several proposals may reuse/extend a consistently represented asset; their partial permissions or transitions need not be replaced by one artificially cheapest action.
- Contractor/edit bundles may purchase several noncolliding asset changes for one cost, so splitting cost into independent edges changes the objective.
- Modular or grid-aligned footprint candidates can give an exact cell model without shrinking any physical envelope.
- A common accessible entrance and many destination obligations create rooted demand semantics without limiting destination count.

These are scenario classes to substantiate with authored/IFC evidence, not proof that a public building currently satisfies the parameter bounds. Long globally coupled shaft choices or moving equipment may require another state extension within the same direction.

## Immediate work toward an originality decision

1. Review the complete resource/owner/completion argument against direct constrained-labelled and incidence-width formulations. Quantify any matching prior bound, rather than treating reuse of one ingredient as rejection of the whole direction.
2. Validate the witness-thinning step: unused graph edges must retain their full geometry and cost. Verify the scope of asset identity consistency and collision-cell equivalence, including EPS behavior.
3. Develop a small set of fully specified repair scenarios with same-asset reuse, partial footprints, multiple profile layers and atomic multi-asset cost. Measure their physical parameters and confirm that the assumptions are not manufactured solely for tractability.
4. Only after the proof and equivalent-method comparison support the claim, implement the necessary witness/recognizer to falsify it, then evaluate. Existing oracle infrastructure is sufficient for that stage; unrelated solver expansion is unnecessary.
